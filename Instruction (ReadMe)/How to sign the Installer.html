راهنمای کامل، قدم‌به‌قدم — برای کسی که هیچی از این موضوع نمی‌داند

چطور Installer.exe را امضا کنیم

این صفحه توضیح می‌دهد NutriculaSignInstaller.exe دقیقاً چه کاری می‌کند، چرا اصلاً لازم است، چطور اجرایش کنید، و نتیجه چه شکلی است — با یک مثال کامل از ابتدا تا انتها. برخلاف NutriculaSignTool.exe (که یک فایل manifest.txt جداگانه می‌سازد)، این ابزار خود فایل Installer.exe را مستقیماً تغییر می‌دهد — در پایان همچنان فقط یک فایل برای توزیع به مشتری دارید.

چرا اصلاً به این نیاز داریم؟ بدون این امضا، اگر کسی Installer.exe را با یک ابزار hex-editor دستکاری کند (مثلاً چک اجباری machine_id را حذف کند)، هیچ‌چیز این دستکاری را تشخیص نمی‌دهد. با این امضا، خود Installer در همان لحظهٔ اجرا شدن، یکپارچگی بایت‌های خودش را چک می‌کند — اگر حتی یک بایت دستکاری شده باشد، Installer از انجام Signup/Transfer امتناع می‌کند.

این ابزار دقیقاً چه کاری می‌کند؟

یک امضای دیجیتال کوچک (۷۲ بایت) را مستقیم به انتهای همان فایل Installer.exe اضافه می‌کند — نه یک فایل جداگانه. این ۷۲ بایت اضافه هیچ تأثیری روی اجرای عادی برنامه ندارد (این موضوع مستقیماً تست شده: یک برنامهٔ واقعی بعد از اضافه‌شدن این بایت‌ها دقیقاً مثل قبل اجرا شد) — چون ویندوز و دات‌نت هرگز بایت‌های اضافهٔ انتهای فایل را نمی‌خوانند، فقط تا جایی که برنامهٔ واقعی نیاز دارد را می‌خوانند.

نکتهٔ مهم: این ابزار فایل exe را مستقیماً (in place) تغییر می‌دهد. اگر روی یک فایل که قبلاً امضا شده دوباره اجرایش کنید، امضای قدیمی را برمی‌دارد و امضای تازه می‌گذارد (نه اینکه امضا روی امضا انباشته شود) — پس اجرای چندبارهٔ آن روی یک فایل کاملاً بی‌خطر است.

پیش‌نیاز

این ابزار باید یک‌بار build شود (دقیقاً مثل SignTool) — با Builders\build_SignInstaller.bat. خروجی در Builders\Builds\NutriculaSignInstaller.exe قرار می‌گیرد.

مطمئن شوید Installer.exe کامل و نهایی build شده است

این ابزار باید آخرین قدم ساخت Installer باشد — بعد از این‌که مطمئن شدید هیچ تغییر دیگری در کد Installer نمی‌خواهید بدهید. اگر بعداً حتی یک حرف از کد Installer را عوض کنید و دوباره build بگیرید، باید این مرحلهٔ امضا را هم دوباره تکرار کنید.

NutriculaSignInstaller.exe را روی فایل Installer.exe نهایی اجرا کنید

از خط فرمان (Command Prompt یا PowerShell)، دقیقاً همین دستور را بزنید:

REM جایگزین کنید مسیر واقعی Installer.exe نهایی خودتان را
NutriculaSignInstaller.exe "C:\path\to\Installer.exe"

همین. هیچ آرگومان دیگری لازم نیست.

پیام موفقیت را ببینید

اگر همه‌چیز درست پیش برود، دقیقاً همین را می‌بینید:

OK: C:\path\to\Installer.exe signed successfully (trailer appended, 72 bytes added).
This is now the FINAL file to distribute to customers - nothing else needed.

همین فایل — دقیقاً همان Installer.exe که الان امضا شد، نه یک فایل جدید — چیزی است که باید به مشتری بدهید. حجم فایل ۷۲ بایت بزرگ‌تر شده (این طبیعی و مورد انتظار است)، ولی اسم فایل و همه‌چیز دیگر دقیقاً همان است.

فایل امضاشده را تست کنید

قبل از ارسال به مشتری واقعی، حتماً یک‌بار خودتان همین فایل امضاشده را روی یک کامپیوتر تست اجرا کنید و مطمئن شوید Signup/Transfer به‌درستی کار می‌کند. اگر فایل را دستکاری‌نشده امضا کرده باشید، هیچ فرقی با قبل احساس نمی‌کنید — فقط حالا در پس‌زمینه یک لایهٔ محافظتی اضافه دارید.

یک اشتباه رایج که باید از آن پرهیز کنید

هرگز این ترتیب را برعکس نکنید: اول Installer.exe را کامل و نهایی بسازید، بعد امضا کنید. اگر بعد از امضا کردن، دوباره کد را عوض کرده و compile بگیرید، فایل exe جدید (کامپایل‌شده) اصلاً امضای قبلی را ندارد — چون این یک فایل تازه است، نه همان فایلی که امضا کرده بودید. باید دوباره NutriculaSignInstaller.exe را روی همین فایل تازه اجرا کنید.

اگر فراموش کنید این کار را انجام دهید چه می‌شود؟

اگر Installer.exe را بدون اجرای این ابزار به مشتری بدهید، وقتی مشتری آن را اجرا کند، چک یکپارچگی (Self-Integrity Check) هیچ امضایی پیدا نمی‌کند و Signup/Transfer برای آن مشتری همیشه رد می‌شود — با پیام:

This installer file appears to have been modified and cannot be used to
activate a license. Please download a fresh, unmodified copy of the
Nutricula installer and try again.

حالت رایگان (Free) تحت‌تأثیر این چک نیست و همچنان کار می‌کند — این چک فقط قبل از مصرف purchase_key/transfer_key اجرا می‌شود.

خلاصهٔ کل چرخهٔ ساخت — کجای این مرحله قرار می‌گیرد؟

#مرحله
۱هر ۹ باینری C++‎ (Service/Broker/DLL ها) را build کنید
۲با NutriculaSignTool.exe، یک manifest.txt برای این ۹ باینری بسازید و در دیتابیس ثبت کنید
۳Installer.exe را build کنید (این ۹ باینری را به‌عنوان Embedded Resource در خودش جای می‌دهد)
۴همین مرحله: NutriculaSignInstaller.exe را روی Installer.exe نهایی اجرا کنید
۵همین فایل (امضاشده) را به مشتری‌ها بدهید
